ריצת סיום אחת הופסקה לאחר שכתיבת קובצי הדוח הפעילה רענון של שרת הפיתוח וסגרה חלונית באמצע תרחיש. זמני בקשות הניווט ב־trace תאמו לזמני כתיבת `CHECKS.json` ו־`REPORT.md`. הריצה הסופית בוצעה בלי שינוי קבצים במהלכה.

ריצות מוקדמות חשפו גם הנחות ישנות בבדיקות: תווית „חלקי”, שם נגיש של התראת סנכרון והמתנה לכותרת במקום לנתוני טופס עריכה. הן הותאמו לחוזה המוצר הנוכחי. בדיקת PWA משתמשת כעת ב־`Response.fromServiceWorker()` כדי לוודא שהמסמך החדש סופק מהעובד, ובודקת גם אפס תעבורת מסמך וכישלון בקשת רשת שאינה במטמון. מדד `workerStart` נשמר כאבחון ואינו משמש לבדו להוכחת מסירת המסמך.

כל כתיבות הבדיקה ומחיקותיה נעשו באמולטורים מקומיים, בפרויקטי demo או בפרויקטי כללים ייעודיים. בדיקות Playwright משתמשות במסלול ההתחברות של אמולטור Google. הבדיקה החזותית השתמשה בחשבון סינתטי מקומי. בדיקות פונקציות השרת הפעילו HTTP מקומי ו־Firestore Emulator; תשובות gov.il ו־data.gov.il דומו.

ייבוא דורש חיבור לשרת לבדיקת היעד והכפילויות. כשל כתיבה לאחר ההכנה נשמר ב־outbox ונבדק בניסיון חוזר. יצירת תדלוקים, שמירתם ופתיחה מחדש ללא רשת נשארו מכוסים בבדיקות PWA.

הגיבוי כולל קובץ תדלוקים וקובץ נפרד לתצפיות ולתוכניות. בקובץ של כמה רכבים בוחרים מקור ויעד ומייבאים כל רכב בנפרד. רשומות שכבר קיימות אינן נדרסות. אין כאן העתקה של זהות Google או שחזור אוטומטי של הגדרות החשבון.

לא בוצעו פריסה, Google אמיתי מול האתר הציבורי, בדיקת iPhone/Safari פיזי, בדיקת קורא מסך מלאה או בדיקת עומס. „אפס התרעות” מתאר את תוצאת `npm audit` בזמן הבדיקה, ואינו הצהרה שאין באפליקציה חולשות אחרות.

## הערות תאימות התלויות

- React Router עודכן ל־7.18.4 ו־Vitest ל־5.0.5. הפרויקט נשאר על React 18. בדיקות Node בוצעו גם על 22.23.3.
- Firebase בדפדפן נשאר בסדרה 11.10. נוספו overrides ממוקדים ל־grpc-js 1.14.6, ל־chokidar 4 אצל Firebase CLI, ל־OpenTelemetry core 2.8 אצל Pub/Sub ול־uuid 11.1.1 אצל gaxios. נבדקו אתחול האמולטורים, צפייה בשינוי קובץ, יצירת לקוח Pub/Sub ויצירת UUID בנוסף לבדיקות האפליקציה.
- פונקציות השרת עודכנו ל־Admin 14.5.0 ול־Functions 7.4.0; יעד Node עודכן ל־22. הקוד כבר משתמש בכניסות ES modules. [הערות Firebase Admin 14](https://firebase.google.com/support/release-notes/admin/node) מפרטות את דרישת Node 22 ואת הסרת ה־namespace הישן. [מדריך Vitest](https://vitest.dev/guide/migration/) מפרט את דרישות סביבת הבדיקות.
- שינויי האפליקציה וכללי Firestore הם יחידת השחרור הנדרשת לתיקוני הפרטיות. הם עדיין לא פורסמו לסביבה החיה.
