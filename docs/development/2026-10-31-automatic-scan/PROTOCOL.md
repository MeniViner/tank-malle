# Frozen evaluation protocol: automatic display scanning

Version 1.0 was frozen in commit `602a098`, before any tuning on TRODO and
before any run on the `test` or `challenge` splits. Changing a rule after that
point requires a new protocol version and a note of which results it affects.
Version 1.1 (section 4a) is the only change; it was made from tuning-split
errors, before the new reader was run on `test` or `challenge`, and the 1.6.0
baseline is re-scored under it.

## 2. Unit of evaluation and grouping

- **Session**: one capture attempt of one display. A TRODO image is a still-photo session. Frames, crops, scales and synthetic derivatives of one image belong to that image's session and group.
- **Group**: an approximation of one physical vehicle. TRODO publishes no vehicle IDs, so images are linked generously (union-find) when they are byte-identical, near-duplicates (64-bit dHash distance ≤ 6), the same odometer type with the same mileage, or the same type with similar odometer crops (dHash ≤ 6) and mileage within 5,000 km. Over-merging costs sample size; under-merging would leak a vehicle across splits.
- Repeated frames or photos of one vehicle are not independent trials. Intervals are Wilson intervals over sessions, plus a group bootstrap (2,000 resamples of whole groups, fixed seed).

## 3. Splits

- `challenge` (unseen display family): every family with 35–60 images, chosen by count before any result: `analog-light-on-dark-blue`, `digital-light-on-dark-green`, `digital-light-on-dark-neutral`. Any group containing one of them is held out entirely. Families are an interpretable proxy (odometer type × polarity × hue of the bright side, measured inside the annotated boxes), not make/model.
- Remaining groups: `tuning` when `sha256("tank-maleh-scan-split-v1:" + group)` maps below 0.35, else `test`.
- Only `tuning` is used for any decision about parameters, thresholds or rules. `test` and `challenge` are run for the before/after comparison; each such run is kept in `benchmarks/scan/runs/` with its commit.

Result (see `benchmarks/scan/trodo-audit.json`): tuning 774 images / 445 groups, test 1,279 / 851, challenge 336 / 92.

## 4. Ground truth and roles

Truth is the dataset's human annotation (CVAT, `groundtruth.json`), never a
model prediction. Each image gets a role from its label and odometer type
alone. The rule was set by looking at sampled crops by eye (the assistant, not
a second human annotator), before any recognition result existed:

| Role | Rule | Scoring |
| --- | --- | --- |
| `eligible` | analog with ≥ 3 digits, or digital with ≥ 5 digits, and the annotated digit boxes spell the label along one row (leading zeros ignored) | Expected value = label; readable and unambiguous |
| `negative-trip-or-clock` | label `0`, a decimal (e.g. `127.8`), or 1–2 digits. Sampled crops (12 of 86 zeros, 11 decimals/2-digit) all show trip meters, clocks or speed, not a lifetime odometer | Any automatic acceptance is wrong |
| `unscored-ambiguous-label` | digital with 3–4 digits: mostly trip meters with the decimal dropped by the annotator | Reported separately, not in the headline metrics |
| `excluded-label-check` | digit boxes do not spell the label (rolling drums, tenths drum included inconsistently, missing boxes) | Reported separately, not in the headline metrics |

Counts under v1.0: eligible 1,958; negative 257; unscored 20; excluded 154.

Known label limitation: on analog registers the white tenths drum is sometimes
part of the label and sometimes not; where its digit box is present and spells
the label, that label is taken as is.

## 4a. Version 1.1: analog registers are reported separately

Tuning-split errors showed that most analog registers end in a differently
coloured drum, usually tenths, and that TRODO labels include that drum as a
digit on most of them but not all (`00719`+white `3` is labelled `7193`; a
neighbouring photo's white drum is left out). The label therefore does not
define the integer the app records: storing `7193` for 719.3 would be a 10×
error. Measuring the drum colour from the boxes did not separate the cases
reliably, so every analog register is now `unscored-analog-register`, and
every report gives its acceptances both ways (matching the label, and
matching the label without its last digit). Analog negatives stay negatives.

Counts under v1.1: eligible 1,223 (tuning 371, test 713, challenge 139);
negative 257 (65, 51, 141); unscored analog 858; unscored digital 3–4 digits
20; excluded label check 31. The headline therefore measures digital
odometer displays only.

## 5. What is run

- **Full frame, capture session (headline).** The whole photograph, EXIF-oriented and limited to 2,560 px (as the app does), through `src/lib/scan/pipeline.ts` `readStill` — the same code the app's worker runs — including its session decision.
- **Before.** The 1.6.0 reader (`scripts/scan-benchmark/baseline-1.6.0/`, byte-identical to commit `4035965`), with the 1.6.0 still-photo flow: 960 px, then 1,280 px, first read accepted.
- **Component (diagnostic only).** `recognizeLine` on the annotated odometer crop. Never a headline number.
- **Synthetic suites (mechanism only).** Reported separately, labelled synthetic.

## 6. Metrics

Defined in `scripts/scan-benchmark/metrics.ts` and tested.

- Exact field correctness and complete-session correctness (all required fields exact; leading zeros and trailing decimal zeros are the only normalisation).
- Accepted precision (correct accepted / accepted); wrong acceptance among all scored sessions and among ineligible ones.
- Correct automation coverage among eligible sessions and among all scored sessions.
- Session and frame abstention reasons; breakdowns by family, role and device.
- Latency p50/p95 of recognition per session; stage times; model download bytes, cold start and memory where measured.

## 7. Targets and verdicts

Proposed targets, not assumptions: ≥ 95% correct automatic completion on
eligible sessions; ≥ 99.5% correctness among accepted readings; warm p95 ≤ 6 s
per scene on a Samsung Galaxy S25.

A target is **met** only when the whole 95% Wilson interval clears it,
**not met** when the whole interval is on the wrong side, otherwise
**unproven**. With n accepted sessions and zero errors, the interval's lower
bound reaches 99.5% only at n ≥ 765; smaller samples cannot prove the
precision target.

## 8. Gates

- A run with any missing or altered corpus file is `incomplete` (exit code 2), never green.
- Pump real-world accuracy, private-photo regression and physical-device latency are **incomplete/unverified** until their data or devices exist; synthetic results do not substitute for them.
