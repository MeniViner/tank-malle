# Cycle 5 — local integration review

המשך מקומי של `26f61d6c5fe4ca0558f043b67aca1e49161525f7`, על בסיס `4b40ce1cc8bbf53e7062066c28be860dd9dc2407`. אין העלאה, PR, פריסה, שינוי מסלול Firebase או פנייה לספקים.

## מה השתנה

- הסריקה כוללת שני שלבים בלבד. אפשר לדלג על צילום ולהשלים ידנית; האישור הסופי בטופס התדלוק. החילוץ מתחיל עם בחירת התמונה. כיוון מסגרת וצבע נפתח כשנדרש תיקון או לפי בקשה. שינוי המסגרת מבטל קריאה ישנה; קלט אנושי נשמר. הזיהוי נשאר ניסיוני, ללא מודלים.
- טיוטות תחזוקה נשמרות מקומית לפי חשבון, רכב, סוג רשומה ורשומה. שחזור עריכה שומר את גרסת המקור כדי למנוע דריסה של שינוי ממכשיר אחר. הטיוטה נמחקת רק אחרי רישום ב־Outbox או מחיקה מפורשת.
- סיכום העלויות משתמש בכל הרשומות ולא בעמוד ההיסטוריה המוצג. חשבונית מרובת עבודות נספרת פעם אחת. זיכוי נרשם כסכום חיובי בקטגוריית החזר ומופחת מהסכום הכולל, ללא שינוי צריכת הדלק. עלות חסרה מובחנת מאפס, לרבות תדלוק ישן. מטמון, קריאות חסרות ופעולות שטרם סונכרנו מסומנים כסיכום חלקי.
- ייצוא היומן אומר במפורש שזה צילום מצב של תאריך בלבד, בלי מעקב ק״מ או עדכון מאוחר.
- ייבוא PDF עם טקסט וטקסט מודבק: חילוץ PDF.js מקומי, עד 5 MB / עשרה עמודים / 100,000 תווים / 15 שניות. PDF ללא שכבת טקסט נידחה להזנה ידנית. אין OCR, מודלים, העלאת קובץ, ביצוע פעולות PDF או פתיחת קישורים. CSV/XLSX מפנים למסלול הייבוא הקיים.
- החילוץ הכללי מציע רק שדות עם תווית מפורשת; סכום קניות/עמלות או מסמך זיכוי אינו הופך לדלק. נדרש אישור סכום הדלק ששולם בפועל. אין מתאם yellow: טרם סופקו מסמכי מקור אמיתיים.
- זהות מאושרת מבוססת על מנפיק, סדרה, סניף ומספר מסמך, כולל אפסים מובילים. נשמרים רק hash הזהות ו־hash הטקסט, לצד נתוני התדלוק המאושרים; הטקסט המקורי אינו נשמר בטיוטה או בענן. זהות נשמרת בעריכה, ומזהה מסמך יציב מונע יצירת עותק באותו רכב במהלך ניסיון חוזר. טקסט בלי מזהים מקבל זיהוי חזרה זהה ורמזי כפילות לבדיקת המשתמש. מסמכים ששונו בלי מזהים אמינים אינם ניתנים לזיהוי ודאי.

## הפעלה מקומית

```sh
npm ci
# Terminal A (Java 21+ on PATH)
npm run emulators:care
# Terminal B
npm run dev:care
```

תצוגה: `http://127.0.0.1:5283`. משתמשי בדיקה בלבד, Auth + Firestore של `demo-tankmaleh`. השרתים קשורים ל־loopback. אין Functions. המסלולים החדשים משתמשים ב־serializer, validation, journal ו־Outbox הקיימים. זהות מסמך היא לפי הרכב; העברת קבלה לרכב אחר היא בחירה מפורשת, ואינה שינוי של הרכב המקורי.

## בדיקה בטלפונים ברשת המקומית

1. מחשב וטלפון ברשת בדיקה פרטית. העתיקו `device.example.json` אל `.care-device/config.json`, ועדכנו את כתובת IPv4 של המחשב.
2. צרו תעודת פיתוח תקפה עבור אותה כתובת (למשל באמצעות [mkcert](https://github.com/FiloSottile/mkcert)). שמרו מפתח ותעודה רק בתיקיית `.care-device/` המוחרגת מ־Git. התקנת אמון בתעודת הפיתוח בטלפון היא פעולה ידנית של בעל המכשיר. אין לבטל בדיקות TLS ואין להעביר מפתח CA לטלפון.
3. הפעילו את האמולטורים ואז `npm run dev:care:device`. התהליך יוצר build נפרד תחת `.care-device/dist` ופותח HTTPS בכתובת שהוגדרה. בדקו שמופיע פס ״תצוגה מקומית״ לפני הזנת נתונים.
4. שער HTTPS מעביר רק נתיבי Auth/Firestore ידועים ל־127.0.0.1. הוא חוסם נתיבי ניהול, פרויקט שאינו `demo-tankmaleh`, Host/Origin אחר וחיבורי ענן ב־CSP. ה־SDK מאמת גם את מקור הדף, מזהה הפרויקט ומצב האמולטורים. נתוני האמולטורים הם נתוני הדגמה; אין בהם הרשאות או זהות אמיתיות ואין לחשוף את השרת לאינטרנט.
5. לבדיקת PWA: פתחו ב־Safari / Chrome, התקינו למסך הבית, וודאו שליטת Service Worker, ואז בדקו את מטריצת החומרה שב־VALIDATION.md.

`npm run build` ב־production חוסם קונפיגורציית demo/emulator. קובץ הבנייה למכשיר נשאר נפרד; אינו ארטיפקט לפרסום. אישור תוכנה אינו אישור מכשיר פיזי.

## דגימות שטח

לא סופקו בסבב זה צילומי צג אמיתיים או מסמכי ספק. תוצאות הסינתזה אינן שיעור הצלחה בשטח.

העתיקו את `field-manifest.example.json` לתיקיית `.care-device/`. כל דגימה מוסיפה:

```json
{"id":"eval-01","source":"real","groundTruthVerified":true,"file":"private/pump.jpg","session":"capture-B","display":"pump-B","displayClass":"upright-seven-segment-dark","split":"evaluation","kind":"total","expected":"287.40","mode":"auto","crop":{"left":80,"top":120,"width":600,"height":160},"entryTimeMs":18000}
```

הערכים כאן דוגמה לסכמה בלבד, אינם מדידה. crop נמדד אחרי תיקון כיוון EXIF והקטנה למקסימום 1280 פיקסלים, כמו מסלול האפליקציה. `entryTimeMs` נרשם רק אם נמדד זמן מלא מפתיחת הטופס עד אישורו; אין להשלים מספר חסר. יש לאמת את המספר הצפוי מול התצוגה המקורית, לא מול הפלט של האלגוריתם. אותה ישיבת צילום ואותו צג אינם יכולים להופיע גם בכוונון וגם בהערכה.

```sh
node scripts/scan-field.mjs .care-device/field-manifest.json .care-device/field-results.json
```

הדוח מפריד tuning/evaluation וכולל שגיאות בקריאות שהתקבלו, שיעור דחייה, כיסוי לפי משפחת צגים, זמן זיהוי וזמן הזנה כולל אם נמדד. תמונות אינן נכללות בדוח או בחבילת הביקורת. `samples: []` מחזיר `pending-no-samples`, ולא ציון הצלחה. לפני הרחבת התמיכה צריך להגדיר משפחת צגים ספציפית, לאסוף דגימות עצמאיות ולבחון גם השתקפות, טשטוש, הטיה ומספרים שאינם ODO.

## בסיס טכני למחקר

- [PDF.js API](https://mozilla.github.io/pdf.js/api/draft/api.js.html): חילוץ טקסט דרך `getTextContent`; PDF.js 6.4.299 מקומי ו־worker מקומי, ללא תלות ב־CDN. גרסה זו הסירה את אפשרות `isEvalSupported`; נבדק המקור המותקן ואינו מפעיל `eval`.
- [getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia): המצלמה דורשת הקשר מאובטח. HTTP על כתובת LAN אינו חלופה ל־HTTPS.
- [Firestore settings](https://firebase.google.com/docs/reference/js/firestore_.firestoresettings): בשער המכשיר מוגדרים host מקומי מדויק ו־SSL; חיבור רגיל משתמש ב־`connectFirestoreEmulator`. שני המצבים מוגבלים ל־demo.

תוצאות מדויקות, SHA ורשימת קבצים יימסרו ב־RECEIPT.md בחבילת הביקורת לאחר הבדיקה הסופית. VALIDATION.md מפריד בדיקות תוכנה מבדיקות חומרה שטרם בוצעו.
